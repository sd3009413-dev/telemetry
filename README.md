# Telemetry

Система сбора, валидации и хранения телеметрии с 4 источников в реальном времени.
Без графического интерфейса. Работает как консольный демон с выводом изменений в stdout.

### Исходные данные

Система собирает телеметрию из **4 источников данных**.

- Сбор значений: **1 раз в секунду** с каждого источника.
- Количество объектов на источник: **от 100 до 600** (в системе — до 1000).
- Тип значений: **целочисленные (int) и булевы (bool)** — в оригинале ТЗ «столярное и були».
- Из каждого источника может собираться **до 1000 объектов**.

### Журналирование и тренды

- В системе журналирования предопределён набор из **20 объектов «тренды»**.
- Значения трендов логируются в БД.
- Для трендов ведётся **самописный WOL-журнал** (Write-Once Log) с постоянным окном видимости на **3600 элементов**.
- Графический интерфейс **отсутствует**.

### Логика обработки

1. При получении объектов из источников — **валидировать значения**.
2. Если значение **валидно** — сохранять в базу **SQLite**.
3. Если значение **не валидно** — **логировать** его (в отдельный лог, не в БД).
4. Тренды логировать в БД и в WOL-журнал.

### Компоненты

| Модуль | Ответственность |
|---|---|
| `config.py` | Декларативное описание источников, трендов, путей |
| `models.py` | Датаклассы `Sample` и `TrendSample` |
| `sourse.py` | Опрос источников (`poll() -> list[Sample]`) |
| `validator.py` | Проверка значений (None / тип / диапазон) |
| `storage.py` | Batch-запись в SQLite (WAL) |
| `trend_wol` | Потокобезопасный кольцевой буфер |
| `trends.py` | Вычисление 20 трендов из окна WOL |
| `main.py` | Планировщик 1 Гц, склейка компонентов |
